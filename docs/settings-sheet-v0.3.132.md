# 设置弹窗连贯性修正（0.3.132）

用户反馈：在 APK 内点击设置项打开弹窗或选择器时，动画割裂、卡顿。用户提供 [Miuix](https://github.com/compose-miuix-ui/miuix) 作为 UI 参考；本次保留 Java/Android View 架构。

## 已确认的窗口问题

旧 `SettingsDialogController` 在 `Dialog.show()` 后通过 `OnShowListener` 设置 88% 屏幕高度和软键盘模式。API 36 虚拟设备的 atrace 显示，每次打开会先执行首次窗口布局，随后约 200ms 再执行 `first=false/resize=true` 窗口布局，重新测量与绘制内容。

只把原有 88% 高度前置的实验没有提供可靠的帧率改善证据。最终实现采用内容适应高度、滚动上限和首次挂载前的最终窗口尺寸，消除进场期间的额外尺寸变更。

## 修改

- 所有由共享控制器打开的设置面板采用同一底部滑入/滑出窗口动画。
- 短设置按内容高度显示，长设置限定滚动区域；窗口宽度最多 420dp，两侧至少预留 12dp。
- 窗口尺寸、键盘 resize 模式和动画在首次显示前设置，删除显示后的尺寸修改回调。
- 高度上限约束整个面板，由实际标题高度分配剩余滚动空间；修复 Android 13、小屏、1.5 倍字体下双行标题使窗口超限的问题。
- 沿用编辑、保存、草稿和生命周期处理，没有修改 SystemUI Hook。

参考上游提交：`106af3001977f4e189e569ec760a9061dc9a4238`。参考对象是 `WindowBottomSheet`、`BottomSheetContentLayout`、`DialogDefaults` 的底部面板、最大宽度及动画方向；没有复制 Kotlin 源码或引入 Compose 依赖。当前原生窗口插值动画不是 Miuix 弹簧动画的完全复现。

## 测量与限制

虚拟设备：`IceBridge_API36`，仅使用显式 serial `emulator-5580`。未连接或安装实体手机，未验证 LSPosed 注入、HyperOS 窗口合成或目标手机帧率。

复测命令（仅接受模拟器 serial）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\measure-settings-jank.ps1 -Serial emulator-5580 -PageTab '状态栏' -ItemText '融合图标' -Iterations 5
```

脚本验证操作实际打开并关闭弹窗、有效帧和窗口轨迹；默认门槛针对显示后的 resize，gfxinfo 帧耗时用于观察。API 33/34/35 设置行为、小屏/大字体、深浅色与键盘空间回归及发布结果以本版本测试报告和归档清单为准。
