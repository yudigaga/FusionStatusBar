## 修改

| 已复现问题 | 修复 |
| --- | --- |
| 原生卡片将 Drawable 清空后，模块仍强制切到需要自绘内容的模糊模式 2 | 保留 OEM 请求的模式 1；仅模块自绘容器使用模式 2。OEM `MiBlurCompat` 将两者分别定义为 `DRAW_RECT_AND_BLEND` 和 `DRAW_CUSTOM_AND_BLEND` |
| 模式 3 的媒体/滑条前景混色被当作背景，造成图标颜色受污染 | 保留 `DRAW_CUSTOM_INSTEAD` 的原生混色与模式 |
| 组件挂载后重新设置背景，留下原生灰色 | 跟踪组件子树中的背景对象变化，在变化时重新应用当前材质 |
| 半透明圆形材质下面仍绘制 OEM 多边形；多个动画背景层会重复混色 | 替换材质时不再叠画原生底板，同一组合只绘制一层选定填充；透明背景保持透明，前景 glyph 不变 |
| 已包装的卡片背景重新注册时，没有处理包装内部真正的背景 | 穿透本模块圆角包装，继续注册原始背景并保留恢复行为 |

`ControlCenterPublishedMaterialTest` 使用上述重读后的配置，覆盖无 Drawable 的原生胶囊模式、挂载后替换背景、真实多边形 Drawable、前景模式、包装后重绑，以及双背景动画层。五个针对缺陷的用例先失败，再修复；双背景层和透明切换也纳入检查。
