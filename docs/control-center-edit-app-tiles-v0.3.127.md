# 原生编辑态隔离与应用快捷开关

日期：2026-10-01。版本：0.3.127 / 141。

## 问题与证据

用户报告原生控制中心进入编辑后滑动卡顿，以及模块只列出系统快捷开关。本轮未收到新的日志或录屏；复查上一份 `LSPosed_20261001_022207.zip`，它主要包含此前推送失败与分发记录，不能作为当前编辑页滑动的帧率测量。

代码确认：磁贴来源原先主要是固定列表、配置顺序和参考采集，缺少 PackageManager 的 TileService 发现。原生编辑态虽然不会安装自定义运行时网格，但外围尺寸、列数、分栏与刷新钩子仍会执行。

修复前三项定向测试失败：EDIT 绑定仍追加 post/postDelayed 两次尺寸修正；延迟回调会改变 EDIT 磁贴的高度；EDIT 分栏刷新会覆盖原生列数并请求布局。这证明了额外干预，不足以证明设备上的全部卡顿都由它导致。

## 原生编辑态

新增 ControlCenterNativeMode，通过原生 mode、controller/provider 及视图祖先识别 EDIT，缓存有界反射访问器但不缓存 mode 值。兼容最低 API 33，不依赖 API 34 才提供的 ClassValue。

EDIT 下跳过磁贴绑定后的尺寸任务、迟到尺寸回调、图标/圆角定制、磁贴和组件跨度覆盖、额外列数与缓存刷新、自定义分栏干预及模块主动适配器重绑。原生方法仍执行；NORMAL 下原有自定义逻辑保留。重复 50 次模拟 EDIT 绑定未追加模块尺寸任务，切回 NORMAL 后仍按配置更新。

没有新增常驻计时器或逐帧日志，没有修改系统动画时长，也没有声称获得真机 FPS 改善。新增 LibXposed 测试依赖只为直接调用实际钩子方法进行回归，APK 中仍为 compileOnly。

## 应用快捷开关

- Manifest 增加针对 `android.service.quicksettings.action.QS_TILE` 的 queries，不申请 QUERY_ALL_PACKAGES。
- 应用进程在后台扫描当前用户可见、启用、导出且声明 BIND_QUICK_SETTINGS_TILE 的服务，读取服务名称、应用名称与图标。一个应用的多个磁贴分别列出。
- 每次回到设置页更新发现结果；读取尚未完成时点击添加会等待结果，暂停后取消待打开动作。不会每次拖动或重绘都扫描包管理器。
- 添加列表按系统快捷开关、应用快捷开关、组件排列，应用项显示真实服务/应用标签；组合成员候选同样可用。应用图标作为本地预览资源，不伪称已读取实时状态。
- 保留配置中的规范化身份，但调用系统原生工厂时使用 PackageManager 返回的大小写正确的 ComponentName，支持短名和完整类名匹配。
- 对已由 SystemUI 提供的实例直接复用；对选中但未加入原生面板的应用磁贴，通过现有 QSController.createTile 建立实例，再走原来的 QSRecord/holder 绑定链路，不修改用户的原生添加列表。
- 模块创建实例以独立引用计数管理，重绑可复用，释放记录后销毁；不会销毁原生 host 拥有的实例。创建失败或应用不可发现时沿用不可用项目跳过策略。

范围为当前用户可见的标准 TileService。未实现跨工作资料用户查询、私有厂商快捷开关协议或第三方应用内部未导出的功能。部分应用仍可能要求自身初始化、权限或登录。不是安装任意应用后都能生成快捷开关。
