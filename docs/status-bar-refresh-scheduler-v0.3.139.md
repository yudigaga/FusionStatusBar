# 状态栏刷新调度职责拆分（0.3.139）

本版本增加 `LatestRootRefreshScheduler`，负责合并异步状态栏刷新请求。它只弱引用最近的 root，同一队列任务运行前的连续请求合并为最新 root；刷新过程中到达的新请求会在当前刷新结束后续排。

调度器通过一个主线程投递器和一个刷新回调运行。投递被拒绝或抛错时会恢复空闲状态并保留待处理 root，等待下一次请求触发重试；刷新回调异常也会释放调度状态。实现不会因 Looper 持续拒绝任务而立即忙循环。布局、配置读取和应用回执仍由 `SystemUiHooks` 负责。

纯 Java 测试覆盖 latest-root 合并、刷新期间的重入请求、弱引用不保活 root、post 失败后的后续重试和刷新异常恢复。没有进行设备验证。
