# 控制中心采集、导入与拖动修正

版本：0.3.122 / 136。输入证据为用户提供的三张截图，未取得本轮真机日志或设备连接。

## 已复现的问题

1. MainActivity 导入只拼接 capturedSpecs 与 capturedComponents，再调用 fromCaptured 按名称重新填格。原始坐标、实际网络横卡宽度、组件插入位置和形状丢失。导入几何的集成测试在修复前失败。
2. 手势 canPlace 拒绝全部占位，提交路径还直接 validate；属性路径把改动项目放前面再 resolve。相同目标出现不同结果。占位拖动提交的集成测试在修复前失败。
3. 拉取图片使用 Bitmap + 软件 Canvas 的 View.draw，未读取已提交的窗口像素。这与截图中内容存在、背景缺失的现象吻合，但不能仅凭本地测试证明所有 OEM 背景层缺失都由此引起。

## 改动

- 新增 ControlCenterCaptureImport，依据同排位置、窄单元宽度与行距推断网格，再映射各项目的 XY、宽高。保留媒体、滑块、设备中心在磁贴之间的位置。导入只替换当前选择的标准或紧凑布局，不复制一份猜测布局到另一模式。
- 间距来自采集像素与源设备 density，写入既有全局间距字段，因此会作用于两套布局；此次导入的撤销同时恢复原间距和原布局。几何冲突时拒绝导入，不悄悄改成顺序排布。
- 新采集数据为 JSON v3 外壳，复用旧 v2 边界串并增加 styles、density；仍支持旧 v1/v2。新增采集元数据不改变布局配置的二进制版本。
- 采集可访问的形状/圆角、状态、文字、滑块进度和独立原生图标，图标限制为 64px，解析限制尺寸与数据量。未知形状回退为圆形小磁贴/24dp 圆角卡片；读取不到的字段继续用本地示意。
- 编辑器使用采集时的状态、文字、图标和滑块数值，背景与形状仍由独立 Renderer 重绘。不是拉伸整卡截图，也不是实时状态连接。采集快照存于原参考缓存中，不写入推送配置。
- 新增 ControlCenterWindowCapture，API 34+ 使用公开 PixelCopy View-window API；API 33 使用 SystemUI 内部窗口 Surface 兼容路径。只复制当前面板的窗口区域，不读取壁纸文件或请求额外权限。
- 保留布局稳定性、异步完成时面板可见性、几何状态复查，以及写出前的请求代号检查。复制失败会回收 Bitmap、释放写入占用并重试；不会以旧的软件绘图冒充完整截图。
- 修正采集去重时先消耗零尺寸项目标识的问题，并继续遍历无法识别 spec 的容器。
- 拖动与属性调用同一 ControlCenterGridPlacement。拖到未锁定项目时保留目标位置并重新安置冲突项目；锁定位置、边界与容量受保护。松手只提交一次，取消不产生记录。

## 验证

修复前两项定向集成测试均失败，修改后通过。全量测试包括旧布局/新元数据解析、图标序列化、采集视图不被修改、真实状态替代示意、布局几何与间距撤销、占位手势、锁定拒绝、取消和独立布局。

本地原生图形测试输出 `app/build/reports/control-center-styles/captured-state.png`，验证开启/关闭背景、采集文字与滑块数值。这是构造数据渲染，不是真机采集结果。

最终执行 `:app:testDebugUnitTest :app:lintDebug :app:assembleDebug` 成功，228 项测试通过，无失败/错误/跳过；Lint 为 0 errors、57 warnings，其中 API 33 的内部 Surface 兼容读取存在隐藏 API 提示。Android 16 使用公开的 API 34+ 分支。apksigner 校验通过，aapt 确认版本 0.3.122 / 136 及 MainActivity 启动入口，打包的 module.prop 版本一致。

## 真机验证与限制

覆盖安装后需重启 SystemUI，使新采集代码生效。随后重新拉取、展开控制中心并等待稳定，再返回导入。旧缓存没有原生样式元数据，不会自行升级。

PixelCopy 读取的是窗口 Surface，不等同于完整 SurfaceFlinger 屏幕合成。若 OEM 把模糊或背景放在独立合成层，仍可能无法完整带入，必须结合新截图与 `capture method=pixelcopy` 日志验证。没有真机证据时不能宣称图一的缺失已完全解决。

媒体内容、设备中心内部动态控件和跨窗口模糊暂未完整移植到编辑器；仍使用原生组件的本地近似渲染。已采集状态只代表拉取瞬间，不能宣称与之后的运行时状态实时一致。拖拽边缘自动滚动不在本次修改范围。
