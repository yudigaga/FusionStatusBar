# FusionStatusBar 后续优化实施计划

日期：2026-10-05。源码基线：主工作区 `0.3.173 / 187`。状态：阶段 0-2 已实施，阶段 3-6 待实施。

本计划将全项目建议落实为独立任务，优先处理控制中心重复重绘、配置无关刷新和插件能力判断，再整理职责与发布流程。每项包含验收与回退条件；本次只编写计划，未修改业务代码、执行构建或操作设备。

## 1. 目标与范围

目标是减少稳定界面的无效工作，使功能是否生效可核对，使 OEM 适配和编辑流程易于维护，并统一可追溯的发布入口。

- 沿用 Java 17、Android View、LibXposed API 102 和现有 app 模块，保留中文界面。
- 复用已完成的草稿恢复、保存失败处理、原子配置、预览代次、后台读取、有界重试与修订号回执。
- 每个行为变更独立提交和验证，结构整理与视觉变化分别交付。
- 本轮默认安排本地实现、测试、构建和文档。设备安装、LSPosed 检查、SystemUI 重启和目标 ROM 验收列为单独的后续工作。
- 实机性能目标在同条件基线采集后确定，当前不承诺提速或耗电改善百分比。

当前有两个发布来源：主工作区仍使用 `com.xtjm.fusionstatusbar`，正式公开版使用 `io.github.yudigaga.fusionstatusbar`。阶段 0 必须先确认正式源码、包名、Provider authority、作用域及签名来源，后续发布沿用对应身份，避免在旧包工作区误发公开版。

| 观察 | 当前证据 | 本轮处理方向 |
| --- | --- | --- |

| 网格每次绘制同步材质、扫描背景和定位装饰 | `ControlCenterRuntimeGrid.dispatchDraw`；材质部分分支无变化仍失效 | 先保证幂等，再引入 dirty 更新 |

| Activity、Hook 和网格职责仍集中 | MainActivity 约 4357 行、SystemUiHooks 约 4513 行、运行时网格约 2131 行 | 按状态所有权与 OEM 依赖拆分；行数仅作参考 |

## 3. 阶段安排

按一名熟悉项目的开发者估算，本地工作约 23-35 个开发日，约 5-7 周；设备准备和目标 ROM 验收另计。阶段 0 完成后按测试时长与实际热点重新校准。

| 阶段 | 优先级 | 主要结果 | 预计工作量 | 依赖 |
| --- | --- | --- | --- | --- |
| 0 | P1 | 正式源码身份、可恢复基线与统一发布入口 | 1-2 日 | 无 |
| 1 | P1 | 材质幂等、dirty 同步与静止面板回归 | 4-6 日 | 0 |
| 2 | P1 | 增量配置、按 loader 能力与完整功能回执 | 4-6 日 | 0；增量材质路径依赖 1 |
| 3 | P2 | 控制中心页面、OEM Adapter 与材质会话 | 6-8 日 | 1、2 |
| 4 | P2 | 经测量确认的缓存、遥测和设置交互优化 | 3-5 日 | 0；缓存生命周期依赖 3 |
| 5 | P2 | 可定位运行时问题且有数据范围控制的诊断包 | 2-3 日 | 0、2 |
| 6 | P1/P2 | CI、本地最终回归及设备验收矩阵 | 3-5 日 | CI 可自 0 并行；最终验收依赖前序 |

第一批交付范围为阶段 0-2：基线与发布入口、材质幂等、dirty 更新、配置 diff 和插件能力判断。该批完成后评估收益，再安排规模较大的职责整理。

## 4. 各阶段任务与验收

### 阶段 0：固定源码与发布基线

1. 核对主工作区和正式源码的差异，记录实际构建 commit、发布 tag 与包名关系；先保留当前用户修改和可恢复的源码快照。
2. 复用 `artifacts/official-releases/v0.3.173/verify-release.ps1` 中已有正式验证逻辑，整理为版本管理中的发布入口，参数化 namespace、applicationId、变体和报告路径。
3. 正式发布要求明确 commit/tag 和可用签名配置；开发 dirty 归档保存完整 diff、未跟踪源码内容与输入指纹。无法还原的历史版本按证据标记，不补造源码。
4. 固定工具链版本与依赖解析输入，记录证书指纹，签名材料留在本机或 CI secret；不通过更换证书解决脚本问题。
5. 对选定基线执行 Debug/Release 单测、lint 和构建；记录首次耗时、报告路径及后续任务使用的源码身份。
6. 改动前保存匹配源码的基线 APK、配置样本和场景定义；准备同步次数、失效次数、反射解析次数等可重复本地指标。诊断字段规范也在此阶段固定。设备采样若延后，保留基线包与改造包供同条件对照，不用旧版数据补充当前基线。

验收：从记录的源码与构建输入恢复工程并通过同一命令验证；两个变体的结果独立归档；公开版 `debuggable=false`，版本、包名、Xposed 元数据、签名和 zip alignment 核验一致。若二次构建 APK 字节哈希不同，检查 ZIP 时间戳、签名和构建输入，不把字节完全一致作为未经验证的承诺。

回退：保留原脚本和已有 APK、源码及配置备份；新入口验证通过后切换。更新计划不触发提交、打 tag、推送或发布。

### 阶段 1：减少绘制中的无效工作

任务 A：让材质更新幂等。

- 保留并核对 `TileSurfaceDrawable.configure` 已有早退条件，向调用方传递实际变化；补齐卡片裁剪背景、备用圆形背景等剩余路径的幂等判断。同一配置、状态、几何和 Drawable 身份不重复失效。
- 区分“该表面已接管”和“本次状态有变化”，检查所有 boolean 返回值调用方，避免用 `changed=false` 误判接管失败。
- 原生 Drawable 的动画回调继续传递；背景替换、状态切换和 bounds 变化仍能触发必要重绘。

任务 B：按事件同步材质。

- 在绑定、挂载、配置变化、图标/背景替换、主题及编辑模式变化处标记 dirty；每个 slot 只在脏时更新。
- 缓存有效形状和 slot/装饰对应关系，减少绘制期间 Item 分配与整树查找。
- 动画中的平移、缩放、变换矩阵仍随帧更新；布局和尺寸重算仅在几何变化时执行。
- OEM 延迟背景更新采用有界兜底，记录触发条件和停止条件；不得重新引入永久整树轮询。
- 挂载延迟任务保存 token 或 Runnable，释放时取消，保留 generation/身份校验。

验收：稳定配置下重复调用 configure 不产生模块额外 invalidation；模拟 OEM 晚到 Drawable、活跃状态切换、按压缩放、主题变化和重新绑定后最终外观正确；释放后旧修正任务不再操作 View。现有形状、遮罩、材质恢复、描边和横屏回归通过。

回退：A、B 分成独立变更；事件同步遗漏时先回退对应 dirty 路径，保留已验证的幂等修复。最终 GPU 合成和持续帧情况留待设备验收。

### 阶段 2：配置增量应用与真实能力回执

任务 A：定义配置 diff 和应用事务。

- 覆盖状态栏、时钟/天气、遥测、通知时钟、控制中心布局/材质、系统菜单/通知表面，写清跨功能依赖。
- 材质变化更新已挂载表面；布局变化才触发重建或重新分发；无关功能保持当前挂载对象。
- 复用已有最新配置合并机制，将一次配置应用的副作用汇入主线程事务，处理应用中再次到来的更新。
- 无行为变化的功能也确认新修订号，保持 applied/waiting/degraded 状态准确；不能因跳过刷新永久等待或错误宣称已应用。

任务 B：按 ClassLoader 与宿主记录插件能力。

- 必需/可选能力、缺失原因和重试预算属于实际 loader；回执根据当前面板所属 loader 判定。
- 成功 Hook 不重复安装，失败或缺失项有界重试；区分尚未加载与当前 ROM 明确不支持。
- 补充 loader A 成功、B 失败、B 后续恢复、活跃 loader 切换和旧 loader 释放场景。

任务 C：补全新功能状态。

- 为电源菜单、音量菜单、通知表面和悬浮通知增加能力及应用回执；安装成功、等待窗口、已应用、降级分别表达。
- 概览和诊断快照可显示实际加载模块版本、运行时 session、配置修订号及失败原因。
- 功能独立降级，某一表面失败不阻止其他功能应用。

验收：仅修改控制中心颜色不触发布局重建或状态栏无关刷新；配置连续更新最终确认最新修订；多 loader 不互相掩盖失败；关闭功能正确恢复原生状态；旧 session/旧 revision 回执不能覆盖新状态。

回退：diff 路径与 loader 状态改造独立交付；依赖遗漏时回退受影响功能的增量更新。新的回执协议采用兼容字段，保留旧配置读取能力。

### 阶段 3：让页面、宿主与材质各自拥有状态

1. 提取 `ControlCenterSettingsPage`，沿用 `SettingsPageController.Model` 模式，页面拥有画布、选择器和编辑动作，通过 `ControlCenterEditorSession` 读取状态。先迁移形状/材质面板，再迁移画布与拖拽，逐步删除 Activity 的镜像状态。
2. 提取 `ControlCenterHostAdapter`，封装 OEM 能力探测、content map、record factory、holder 创建/绑定和原生恢复。运行时网格接收已解析宿主对象，随后将 GridView 的测量与绘制独立整理。
3. 为同一 root/tile 建立 `MaterialSession`，集中原生快照、包装 Drawable、有效策略和恢复操作。先迁移形状裁剪与背景包装，再按实际需要迁移其他状态表。
4. 运行时通过稳定的包级入口应用、恢复并返回状态；日志与回执复用协调器传入。相关测试逐步从私有字段反射转为同入口的行为测试。

验收：编辑、撤销、草稿恢复、预览和推送仍通过现有行为测试；新增一个材质字段或一个 OEM 差异主要修改所属模块；所有恢复操作可重复执行，异常不会阻断剩余释放。不以固定文件行数作为验收标准。

回退：每次只迁移一条行为链，保持旧入口适配至新模块，验证后删除重复实现；按链路回退，不同时改配置格式和视觉默认值。

### 阶段 4：通过测量决定其他性能改动

| 任务 | 实施方式 | 验收与退出条件 |
| --- | --- | --- |
| 缩小高频 Hook 工作 | 先记录调用数、未管理对象进入率和耗时，保留现有身份检查；将快速判断前移并对相同值短路 | 非本模块管理对象保留原生语义；原生重建对象仍可注册；只有确认热点后收窄拦截范围 |
| 反射缓存有效寿命 | 优先由 HostAdapter/宿主会话持有已解析访问器；正/负结果复用；必要时引入有容量上限的缓存 | 相同宿主重复查询不重新扫描；成员语义不变；释放后不永久保活旧 loader；API 33 可运行 |
| 遥测按需求采样 | 复用已有熄屏取消与方法缓存；先记录接口枚举、文件 I/O 和消费者可见性，再试验分项周期 | 网络切换重置速率基线；温度等慢指标的延迟可接受；无消费者不采样，恢复时读数正常 |
| 设置面板呈现方式 | 针对历史首窗慢点，独立试验 Activity 内面板与当前 Dialog，固定相同操作场景 | 键盘、返回键、焦点、无障碍、主题、大字与窗口层级正常；整体交互延迟有稳定收益才保留 |
| 几何/Path 缓存 | 仅在帧 trace 证实仍为热点时，按 bounds、shape、density 缓存 | 尺寸、密度及形状变化刷新缓存；像素回归通过，目标 GPU 外观正确 |

采样周期先作为实验参数，不直接将所有电池/GPU 项统一改慢。每项形成独立结果记录；收益不足或兼容回归时恢复正式实现，保留实验数据。

### 阶段 5：使诊断包能直接说明运行时状态

- 增加实际加载版本、SystemUI PID/session、已读取/已应用修订号、功能状态、能力缺失和采集时间；对采集期间状态变化作标记。
- 默认提供模块相关日志与必要元数据，完整 logcat、dmesg、LSPosed 日志由用户明确选择；配置内容只导出定位所需字段。
- 对标识符、账号、路径和敏感配置采用字段控制及文本脱敏，明确完整日志的数据范围；保留诊断所需的事件关联。
- 复用现有单条 16 MiB 限制和超时逻辑，补充总容量/总时间预算、截断标记、取消处理与临时文件清理。
- 将导出测试补到超时、部分来源失败、大日志、权限不足、中断和敏感字段场景。

验收：一个包能区分“APK 已更新但旧模块尚未重载”“配置已读取但等待挂载”和“Hook 能力不足”；敏感测试内容不原样输出；包大小有上限、失败有原因、取消后无残留任务与临时文件。

回退：诊断元数据使用版本化格式；日志范围开关独立于运行时行为，导出失败不影响正式配置和 SystemUI。

### 阶段 6：CI 与最终验收

CI 可在阶段 0 后并行接入：普通变更运行单测、lint、无秘密材料的构建和工具回归；正式发布沿用同一验证入口，从签名 secret 生成公开 APK，再归档校验结果。报告区分变体、源码身份和设备范围。

本地验收矩阵：

| 范围 | 必须检查 |
| --- | --- |
| 配置与编辑 | 旧备份/布局读取、草稿恢复、撤销、保存失败、快速提交和新回执 |
| 运行时 | 绑定/重绑、晚到背景、连续材质变化、原生编辑、关闭恢复和释放异常 |
| 平台与界面 | 现有 API 33-35 Robolectric 矩阵、可用的 API 36 模拟器、横竖屏、主题、大字体、键盘与返回键 |
| 发布 | Debug/Release 结果、lint 高风险门禁、版本/包名/证书/Xposed 一致性、签名、alignment、源码恢复 |
| 工具与诊断 | 脚本失败行为、归档防覆盖、状态快照、脱敏、容量、取消与超时 |

API 36 模拟器验证设置应用行为，不能据此认定 HyperOS Hook 或 GPU 合成通过。Robolectric 若需升级才能支持新 API，应作为独立工具链变更验证。

目标设备后续验收矩阵：

| 场景 | 记录与通过条件 |
| --- | --- |
| 安装与模块重载 | 核对 APK 哈希、签名、作用域及实际加载版本/session；安装结果与注入结果分别记录 |
| 控制中心 | 材质/形状/描边、活跃切换、滑条、组件、横竖屏、主题、原生编辑、关闭恢复；有最终视觉证据 |
| 状态栏与通知 | 双排、长时钟、遥测、通知时钟、通知/悬浮通知；新修订回执对应实际界面 |
| 系统菜单 | 电源与音量菜单外观、短款音量、取消和限制状态；危险重启动作通过测试替身验证，设备执行单独安排 |
| 生命周期 | 冷启动、SystemUI 重启、锁屏/亮屏、连续开合；无本模块导致的崩溃或无法恢复 |
| 性能与资源 | 同设备/布局/刷新率做模块开关及优化前后对照；核心开合各至少 30 次，保留帧分布、CPU/PSS及对象数量趋势 |

使用实际刷新率对应的帧预算。主线程 doFrame wall-clock、CPU 时间和显示器 present 时间分别报告；历史 0.3.144 数据不作为当前版本基线。后台唤醒和功耗另做较长时段对照，短测不证明无泄漏或省电。

缺少目标设备证据的版本可以交付本地验证包，兼容性继续标记为未验证；对应 ROM 验收完成后再更新支持记录。
