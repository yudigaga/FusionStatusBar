# 原生磁贴重启恢复 v0.3.163

本版针对切换容器背景后，在 APK 内点击“重启系统界面”导致多数小磁贴底板和描边消失的问题。构建号 177。修复针对通用绑定和重启时序，覆盖全部背景选项。

## 日志证据

输入为 `LSPosed_20261004_190835.zip`。其中 `log/modules_2026-10-04T17:35:58.3171.log`：

- 第 2430 行确认运行版本为 0.3.162 / 176。
- 第 2652–2654 行在 19:04:33 记录自定义布局变为空；之后四次重启均读取空布局。最终截图走原生布局路径。
- 第 3512、3580 行确认原生材质接口 5/5、控制中心 38 个 Hook 已安装。
- 第 3683–3699 行记录全部组件和 11 个小磁贴绑定成功，未绑定不能解释底板缺失。
- 本段未发现对应的 Java fatal 或 native crash，进程退出与用户使用 APK 内重启按钮吻合。

## 原因与修复

| 问题 | 修改 | 回归证据 |
| --- | --- | --- |
| 重启首次绑定时，原生 ImageView 已存在，但异步图标尚未到达；查找逻辑将其跳过，导致装饰层挂到无有效轮廓的外层 | 表面归属不再依赖 glyph 是否已经加载 | 立即加载、延迟加载两条路径的描边像素一致；覆盖所有容器选项 |
| 原生磁贴部分模式只保留 glyph，底板由 OEM 模糊机制提供，缺少显式材质恢复 | 为 glyph-only 原生磁贴恢复所选背景，并沿 OEM 实际轮廓绘制；切回原有背景或关闭模块时还原 | 所有自定义背景颜色和透明度、前景保留及还原测试 |
| OEM 之后重新生成图标或切换背景绘制模式，原生绑定阶段的处理未再次执行 | 在真正完成 `updateIconInternal` 后重新处理原生材质；自定义网格仍由其自身路径管理 | 延迟 Hook 注册及 glyph-only 到 Drawable 背景切换测试 |
| APK 内重启按钮立即执行结束 SystemUI 命令，没有等待已提交配置写入 | 刷新普通设置的延迟保存，等待进行中的写入和显式发布；保存失败取消本次重启 | 普通保存、连续编辑、控制中心发布、失败、重复点击及 Activity 销毁测试 |

重启按钮继续保留已有草稿/发布边界：未推送的控制中心草稿不会因为重启被自动发布。

配置变化日志增加容器枚举、三类模糊强度及描边状态，便于后续核对持久化值。

## 验证与限制

冷启动描边、glyph-only 背景和更新 Hook 的新增用例均在修复前运行失败。修复后的针对性测试通过，再使用 `tools/release.ps1` 执行全量单元测试、lint、构建、签名和版本一致性检查。准确数量与 APK SHA-256 见 `artifacts/releases/v0.3.163/release.json`。

没有在实体手机安装、执行实际重启命令或进行 HyperOS 画面验收。测试中的重启命令被计数回调替代，不会操作设备。
