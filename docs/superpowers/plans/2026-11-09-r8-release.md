# R8 Release implementation and verification plan

User request: enable R8 before publishing the latest completed `0.5.24 / 238` build.

The publication checkout was restored from the immutable 0.5.24 source archive. The original development checkout remains untouched. The existing unoptimized archive remains the size and source baseline.

1. Confirm that `:app:minifyReleaseWithR8` does not exist in the baseline build. Enable Release minification with `proguard-android-optimize.txt` and a narrowly scoped module rule file. Preserve the existing resource packaging configuration in this first R8 release.
2. Keep the `FusionModule` class name, its public no-argument constructor and API 102 callbacks. Let AGP/AAPT rules cover Manifest components and XML View constructors, and dependency consumer rules cover library boundaries. Do not keep the entire application or UI libraries.
3. Build the optimized Release and retain mapping, configuration, usage and seeds. Run both full unit-test suites, both lint variants and tool regressions. Inspect the optimized APK itself: Xposed metadata and entry class, callback signatures, compile-only API exclusion, Manifest components and launcher alias, XML View constructors, enum-backed configuration identifiers and packaged resources.
4. Sign with the existing official certificate and verify package/version, non-debuggable status, v3 signature, 16 KiB alignment, size and SHA-256. Record the actual optimized build source and distinguish JVM/static checks from unperformed device/ROM checks.
5. Publish the new signed APK, exact source snapshot, checksum and validation/R8 reports to the main and LSPosed repositories after the checks pass. Preserve the existing non-R8 archive rather than replacing its evidence.

Risk focus: dynamic module loading by name; host reflection versus module names; XML-inflated custom Views; stable enum/configuration names; and attributing pre-minification unit tests to optimized runtime behavior. Actual LSPosed/ROM execution requires a device and is not implied by the host checks.
