# 磁贴形状分支修复 v0.3.166

本次对照：用户将 5G、自动亮度改为“大圆角”，其他小磁贴保留“圆形”。前两者出现外框与内部圆底，后者仍显示多边形残影。另反馈导入为“自定义”的部分组件在重新选择预设后恢复。

## 已确认的分支缺陷

`ControlCenterCardStyle.ROUNDED` 表示 `RECTANGLE + 40dp`。旧 `ControlCenterRuntimeGrid` 只有 `CIRCLE` 才登记和同步原生小磁贴内部底板，而矩形仍创建全格子的背景和描边。原生网格材质通用处理又明确跳过被自定义网格管理的磁贴，因此不会补偿遗漏。

结果是外层格子被设成大圆角，内部 OEM ImageView 仍绘制自己的圆形底色，且原生颜色遮罩未进入自绘底板的接管分支。这与用户对照图中 5G、自动亮度的双层外观一致。

本版让所有非圆形小磁贴进入底板接管路径，由格子背景统一绘制形状和状态色，内部 ImageView 保留 glyph，抑制其原生独立底板。关闭和重新绑定时还原原始 Drawable。圆形仍保留既有内部表面对齐方式，不把圆形强行扩大成格子大小。

## 自定义与预设

“自定义”只是当前形状/半径未匹配命名预设时的显示名，没有独立的遮罩开关。重新选择预设会修改几何参数并触发布局重建，可能使不同绘制层暂时重合。这个现象不证明 JSON 有损坏，也不能证明全部遮罩都有同一原因。

## 尚未确认

默认圆形中的多边形具体来自哪个原生图层，目前不能只凭截图确认。本版在 5G、自动亮度、护眼和夜间模式的首次有效绘制后记录一次 `tile surface layers`：视图层级、背景/前景类型、ImageView 图层与边界、图像矩阵、材质接管状态和捕获到的原生接口。不记录标签、SSID 或屏幕正文；每个绑定实例只记录一次，层数与长度受限。

这些数据用于区分实际表面选择、前景覆盖、glyph 内嵌底板和原生硬件状态，避免继续按形状猜测。

## 本地验证

`ControlCenterTileShapeIntegrationTest` 从 GridView 的真实分流入口创建圆形原生底板，再选择大圆角和其他非圆形预设；覆盖开启/关闭切换、全格子单色填充、glyph-only 与分层图标、释放后恢复。两个集成用例在修复前失败，修复后通过。既有圆形对齐和胶囊几何测试保持通过。

全量测试、lint、版本和签名结果见 `artifacts/releases/v0.3.166/release.json`。未安装实体手机，不能宣称默认圆形的实机残影已经解决。
