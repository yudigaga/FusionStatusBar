# 全局描边空心路径 v0.3.171

## 实机对照

用户在 0.3.170 中对比音乐/融合中心的柔和圆角与胶囊：圆角整体偏浅，胶囊为预期深色。`LSPosed_20261005_022227.zip` 的组件记录显示两种形状都已使用 `TileSurfaceDrawable`，填色 `c03c4149`、软件接管开启、outlineAlpha=0、nativeBgBlur=0/0，没有取色分支差异。这些记录在首次绘制前采样，不能证明最终合成像素。

用户进一步确认：保持柔和圆角和柔光玻璃，只关闭全局描边，两个组件立即恢复与未开启磁贴一致的深色。由此将当前差异定位到描边开启后的绘制路径，而非配置颜色本身。日志另有厂商 HWUI 的 `DDRE Debug DrawPath: smoothCornerEnabled = true`，但缺少目标 View 和胶囊时段的同类对照，不能将特定厂商底层实现当作已证实根因。

## 兼容处理

原实现向 Canvas 提交实心形状轮廓，并依赖 `Paint.Style.STROKE` 只绘制边缘。本版在提交绘制前用 `Paint.getFillPath()` 将描边展开为实际空心区域，再按 FILL 绘制。即使渲染路径丢失描边语义，也没有中心区域可以填色。保留现有颜色、宽度、抗锯齿、柔光渐变、布局、底板和绘制顺序；原生任意路径的向内描边裁剪保持原有规则。

## 验证

新增回归模拟“描边路径被作为填充路径处理”的已观察结果：旧实现会把深色中心染成浅灰，新实现保持中心像素并保留可见边缘。该替身只模拟失败模式，不声称复刻了目标 ROM 的 GPU 实现。另补全所有组件预设的柔光玻璃和全局描边组合测试；既有描边、柔光和硬件 RenderNode 测试继续通过。

全量测试、lint、签名和版本核验结果见 `artifacts/releases/v0.3.171/release.json`。未安装或操作实体手机；最终需在柔和圆角下重新开启全局描边确认。
