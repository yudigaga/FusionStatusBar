# 控制中心遮罩、设置和时序检查 v0.3.165

本轮覆盖磁贴、Wi-Fi/移动数据/蓝牙卡片、亮度/音量轨道、分组、画布预览、全局外观设置、导入发布、原生 Hook 和运行网格挂载/释放路径。目标是修复与截图相关的设置覆盖和原生材质残留；不将本地测试描述为 HyperOS 实机验收。

## 用户要求的配色

- 已开启的磁贴和二态卡片共用浅色底 `#F8F9FB`。
- 未开启的使用当前容器材质的底色；原有背景保留原生行为。
- 透明材质保持透明；卡片/磁贴强度按既有规则影响透明度，柔光玻璃底色不随模糊强度变淡。
- 亮度/音量的填充继续表示数值。媒体和设备中心没有可通用判定的开关状态，使用普通容器底色。
- 画布预览、普通 Drawable、原生混色和自定义圆形底板采用相同状态配色，开启的浅色卡片使用深色中性文字。

## 查出的冲突

| 问题 | 证据 | 处理 |
| --- | --- | --- |
| 原生高光/阴影独立于背景 Drawable | OEM `HyperMaterialUtils.applyViewMaterial` 另外调用 `setMiBloomStroke`、`setMiShadow` 和 `setMixEffectEnabled`，旧模块只处理五种模糊接口 | 新增精确签名 Hook；仅控制中心范围内、被自定义装饰接管时抑制原生高光和阴影，保存最新原始请求用于恢复 |
| 绘制自定义圆底后仍启用原生颜色遮罩 | OEM 图标状态动画会重新调用 `setMiViewBlurMode(1)` 和混色 | 已有自绘底板的图标独立接管颜色合成，同时拦截后续动画重装；保留背景模糊参数，关闭或退出时恢复 |
| 滑条叠加三套圆角 | 网格外框、`toggleSliderInner`、`progressBg`/`progress` 原先使用不同半径，原生主题刷新还能再次覆盖 | 轨道、描边来源和内层裁剪统一到发布的形状；进度保留数值比例，原生进度边界圆角被轨道半径约束；重挂载和主题更新后重施，释放时恢复 |
| 全局圆角覆盖独立形状 | 原生 `setEnabledBg`/`getCornerRadius` Hook 不区分画布计划 | 有画布计划时停止旧的全局圆角覆盖，由项目形状管理 |
| 独立圆角 0 的含义不一致 | 网格按全局默认值，材质回调却使用短边 18% | 统一跟随全局默认圆角，包括全局为 0 的直角 |
| 磁贴透明度未跟随设置 | 自绘圆形底板忽略 `tileBlur`，预览和普通 Drawable 却应用它 | 对非柔光玻璃材质统一透明度强度，保留前景图标 |
| 开启底色规则在不同渲染路径不一致 | 原生卡片、画布与圆形磁贴各自有一套规则 | 按本轮用户要求统一为开启/关闭两套状态色 |
| 退出网格后仍可能带着自绘状态 | 图标混色接管、包装 Drawable、轮廓缺少统一释放 | 在网格解绑和原生重新绑定时释放接管，恢复原始轮廓、背景及最新原生材质请求 |

## 加载与设置检查

已检查配置复制、旧格式导入、画布计划、草稿/发布边界、APK 内重启等待保存、插件延迟加载、首次绑定、延迟图标更新、资源刷新、动画更新、滑条重挂载及网格解绑。

上一份日志已经证明 0.3.163 重启后正确读到 15 项布局、SOFT_GLASS、三项强度 100 和描边开启，本轮没有新证据支持将问题归因于配置保存丢失。旧分组背景/描边字段按已有全局外观设计保留但不再独立生效，不是导入解析损坏。

`ControlCenterNativeEffects` 处理独立硬件效果的参数策略，`ControlCenterMaterials` 处理作用范围、原始请求记录和恢复。Hook 的内部调用受重入保护，避免清除参数被误记成原始参数。启动日志增加 `native effect APIs` 的能力计数；调用失败记录具体方法。

## 验证

新增和扩展用例包括：

- `ControlCenterNativeMaskTest`：底板接管、原生动画再次写入、关闭恢复、复用为原生磁贴后恢复。
- `ControlCenterSliderMaskTest`：垂直/水平轨道、胶囊缩放、全局默认半径、原生资源刷新、挂载观察者迁移、释放还原。
- `ControlCenterAppearanceContractTest`：全局默认/独立形状优先级、0/25/100 强度、开启/关闭底色、卡片中性文字对比度。
- 既有导入 fixture、模糊模式、材质恢复、画布像素、旋转、分组和重启写入测试。

遮罩接口、滑条和设置冲突分别先运行出失败断言，再实施修复。原生硬件效果通过真实入口参数及生命周期的测试替身验证；普通底板与预览通过 Robolectric 像素测试。它们不能证明厂商 GPU 最终合成画面已经完全正常。

准确测试数量、lint、签名和 APK 哈希见 `artifacts/releases/v0.3.165/release.json`。本轮未安装实体手机，也未执行手机重启。
