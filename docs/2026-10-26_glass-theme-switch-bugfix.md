# 自动日夜切换后的玻璃倒角同步修复

用户反馈：2026-10-25 夜间倒角正常，2026-10-26 系统自动转日间后只有部分倒角显示或状态不一致，重启 SystemUI 才恢复。基线为 `0.5.15 / 229`，本轮候选为 `0.5.16 / 230`。

## 已复现的边界

测试保留同一个 View、Drawable 和设置对象，只更新消费 View 的资源配置，不重新创建 Activity、不重推设置、不手动触发配置回调。

- 自动主题用例初始 8 项中 7 项失败，覆盖已有 overlay、真实 Grid DecorationView、系统表面、通知背景、离屏注册后重挂、独立资源上下文和密度变化。
- 资源组及硬件缓存用例 3 项全部失败：窗口先转日间、插件稍后转日间时卡片仍保留夜间底色；旧 root 合并到日间窗口会吞掉待应用的主题变化；仅执行根 pre-draw 时 Grid 的旧 shader 未改变。
- RED 日志与 XML 位于 [theme-switch-20261026](../../analysis/theme-switch-20261026/)，其中 `red-resource-groups.xml` 固定了 3 项资源组失败。先前 `theme-red.log` 为第一批 10 项的运行记录，避免把重复执行计作额外测试。

## 原因与处理

| 原因 | 处理 |
| --- | --- |
| 倒角的 daylight 只在 configure 时赋值，尺寸不变会继续命中旧 shader | 按实际消费 View 当前配置检查 profile；绘制前可自愈，挂载时也同步 |
| Grid 装饰直接使用 SoftGlass，没有进入普通卡片的 GLASS_VIEWS 集合 | 材质主题批次同时更新 SoftGlass 的完整状态集合，并使改变的显示列表失效 |
| 观察器只盯窗口配置，插件资源可能稍后才更新 | 按实际消费资源组检查变化，不强制所有 View 使用窗口的模式 |
| root 归并时直接记录当前模式，可能吞掉旧材质尚未刷新的变化 | 迁移前保留变化判断，有待应用变化时补一次刷新 |
| 系统背景半径只在 configure 时缓存 density | 背景及 outline 使用当前消费 View 的 density，与倒角一致 |

新增回归还覆盖同一实例连续日→夜→日、稳定 shader 身份、预热后 0 次描边轮廓重算、0 次额外倒角失效，以及稳定根帧不重复扫描背景或调用原生材质 setter。既有开合提速、透明端点及形状缓存保持原有契约。

主题检查以少量资源组为单位；仅在资源变化或待处理的 root 迁移时进行材质刷新，不逐帧扫描整个视图树。仅依赖下一次 Drawable.draw 不足以修复硬件显示列表复用，因此测试要求 root pre-draw 后、任何新绘制之前，已存在的 Grid shader 就更新并且只失效一次。
