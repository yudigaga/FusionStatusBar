# 设置开合慢帧诊断与当前版本复测

日期：2026-10-02。版本：0.3.144 / 158。设备：b7015e9b，Xiaomi Pad 5 Pro / Android 16 / API 36，1600×2560，360 dpi。

本轮完成慢帧归因、实际加载版本核对，以及遥测设置、布局设置、控制中心选择器、冷启动各 30 次采样。唯一的预量实验没有显示整体收益，已回退；应用代码保持正式 0.3.144 行为，未发布新的性能版本。

## 实际加载版本

安装包是 0.3.144 / 158，但重启前运行时回执仍为 0.3.143 / 157，SystemUI PID 仍是 3754。因此历史 `am force-stop com.android.systemui` 和概览的连接标签不能证明模块已更新。

完整重启后读取 `run-as` 可访问的 DE `fusion_activation.xml`，确认模块回执为 0.3.144 / 158、SystemUI PID 为 3799，修订号读取和应用均为 1。状态栏、通知时钟回执为 applied；控制中心仍为 waiting:control_center_mount_pending，这不代表实际自定义控制中心布局已通过 OEM 挂载验收。

当前四组采样的安装 APK SHA-256 均为 `53cf144c8f302ab08d16e20813d8f6b72270a08b7b764b7b2a48f42324729018`，与正式归档相同。编辑器与冷启动脚本还核对了运行时版本、PID 和开机身份。设备未改刷新率、动画倍率、字体或正式配置；显示信息的内置屏幕快照为约 60 Hz，系统支持动态刷新，未证明整段采样中刷新率始终锁定为 60 Hz。

## 已有慢帧与当前版本

历史两组 0.3.143 trace 均完整保留 30 次首次开窗，无缓冲覆盖，主线程 B/E 无未配对结束或未结束开始。遥测设置首次 doFrame 平均 91.329 ms、P95 99.872 ms，布局设置平均 70.906 ms、P95 82.348 ms；其余帧 P95 分别为 6.977 和 14.699 ms。

当前 0.3.144 复测：

| 场景 | 次数 | gfxinfo Janky | 首次 doFrame 平均 / P95 | 结构与行为 |
| --- | ---: | --- | --- | --- |
| 状态栏监测 | 30 | 61 / 1574（3.88%） | 102.525 / 121.302 ms | 30 个首次开窗，显示后二次 resize 0 |
| 状态栏布局 | 30 | 57 / 1580（3.61%） | 67.671 / 80.339 ms | 30 个首次开窗，显示后二次 resize 0 |
| 控制中心卡片样式 | 30 | 180 / 2834（6.35%） | 63.056 / 79.412 ms | 每周期打开、展开、收起、关闭，始终同一编辑窗口 |
| 冷启动 | 30 | 逐进程记录，不能使用最后一次 renderer 代表全部 | 启动 TotalTime 平均 1353.767 / P95 1464 ms | 30 个新进程，30 次最终进入概述 |

doFrame 列来自主线程 trace 的 wall-clock，即包含等待的总时间；它不是 CPU 时间，也不是显示器实际 present 帧耗时。控制中心选择器展开/收起平均 38.229 / 28.807 ms，且每次各有一次因内容高度变化引起的 resize，不能套用设置面板的零 resize 门槛。选择器脚本包含焦点检查和 UIAutomator 等观察开销，不可把其 Janky 与纯开合脚本直接比较。

在遥测首次 doFrame 中，测量总量平均 32.561 ms、窗口 relayout 平均 25.670 ms、Record View#draw 平均 16.390 ms；布局分别为 15.990、22.419、9.319 ms。耗时集中在每次新建窗口的首次布局、窗口服务往返和初次绘制。测量和等待部分与系统服务/渲染相关，不能全部归因应用 CPU。

## 预量实验及回退

只试验在 `Dialog.show()` 前按最终宽度预量面板。原版与实验各采样 5 次：

| 指标 | 正式版 | 预量实验 |
| --- | ---: | ---: |
| 首次 doFrame 平均 | 108.266 ms | 97.241 ms |
| 触摸处理结束到首次 doFrame 开始平均 | 126.401 ms | 136.865 ms |
| 触摸处理结束到首次 doFrame 结束平均 | 234.667 ms | 234.106 ms |
| gfxinfo Janky | 3.72% | 3.80% |

整体区间几乎不变，5 次波动也不足以证明收益。trace 没有为预量调用单独打标，因此不能证明它究竟如何影响了帧前空档；也不能用 doFrame 结束替代实际显示呈现时间。实验代码已回退，设备重新安装正式归档 APK，后续 30 次均使用正式 APK。

## 资源与状态检查

控制中心编辑器的 0/10/20/30 次检查点：Views=776、ViewRootImpl=2、AppContexts=5、Activities=1 均稳定；PSS 为 151074 / 155738 / 154875 / 155593 KB。冷启动各检查点 Views=688、ViewRootImpl=1、Activities=1 稳定，PSS 为 144063 / 125638 / 127762 / 124145 KB，但每轮是新进程，不能将其用作同进程泄漏测试。

两个新场景首尾正式配置文件哈希均未变；首尾回执版本/PID/开机身份核对一致。未看到本轮短测中的对象持续增长，但没有声明长期无泄漏。未在指定 trace 流中观察到 GC 标签，也不能据此证明没有 GC。冷启动检查只验证稳定后的概述页，尚未用逐帧录屏证明过程中没有瞬间闪现。

## 工具与证据

- `tools/measure-settings-jank.ps1`：保留原始 gfxinfo/framestats、包哈希/PID、显示信息、测量后 CPU/PSS；拒绝覆盖，检测缓冲覆盖和缺失开窗，Windows PowerShell 5.1 的 UTF-8 BOM 已修正。
- `tools/analyze-settings-trace.py`：按线程和 marker PID 配对，报告缺失事件；可用 `--expected-openings` 和 `--max-opening-frame-ms` 生成诊断红绿信号。50 ms 仅是捕捉本次稳定慢窗的诊断阈值，不是产品帧预算。
- `tools/measure-settings-flows.py`：冷启动/编辑器逐周期 trace、焦点和 UI 核对、配置哈希、运行时回执、资源检查点；不修改正式配置。
- 新工具 13 项回归通过，PS 语法和 git diff 检查通过。应用源码回退后与实验前一致；既有正式 APK 的 592 项单测和 lint 结果保留，不将工具测试计入 Android 单测数量。

证据原件位于 `build/perf/real-v0.3.144-b7015e9b-20261002-*` 和 `build/perf/runtime-verification-20261002/`；本轮独立补充包位于 `artifacts/validation/v0.3.144/20261002-diagnosis/`。正式发布归档及原始基线保持独立，补充包不宣称所有 ROM/视觉矩阵已通过。
