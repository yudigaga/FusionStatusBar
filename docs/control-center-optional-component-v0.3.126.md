## 原因与修正

ControlCenterRuntimeGrid.apply 在 resolveForRuntime 之前检查原始计划中的全部组件；只要一项没有出现在当前原生 adapter 的来源集合中便调用 abort。该检查甚至包含隐藏项，绕过了布局解析器本来具备的“过滤不可用项目”能力。

移除整套回退前置条件，使用当前 adapter 的 availableSpecs 解析布局。不可用项目仅从本次渲染中跳过，已保存计划不变，其他项目继续保持原坐标。日志记录跳过的标识。若组件在原生初始化完成或样式切换后重新出现，下一次分发会重新加入，不需重写配置。

如果所有项目都不可用，继续保留原生面板，不挂空代理。真实绑定异常、协议不兼容等错误仍保留原有回退保护。本次不扩展跨原生左右 adapter 的组件迁移能力。

“添加项目”中，无参考采集的组件标记“未验证”；最近一次采集未包含的组件标记“本次未检测到”。这只是上次采集状态，不冒充实时能力探测，不禁止用户预先编辑，也不删除既有草稿。
